## Context

`spa-frontend/` has **zero tests**. It is ~2,500 lines of Vue 3 / Vuetify 4 that owns
everything a student touches: registration, key download, key restore, and the public
scoreboard. It recently went through major upgrades (Vuetify 3→4, vue-router 4→5,
pinia 2→4, vite 6→8) and the only thing that verified any of it was that the
`frontend-proxy` image still built. One real regression from that upgrade — the
`v-select` selection slot in `Register.vue` reading `item.raw.title` instead of
`item.title` — was found by hand, not by a test.

Three further gaps turned up while surveying:

1. **`tests/api/` never runs.** 141 tests across 7 files, absent from `testpaths` in
   `tests/pytest.ini`. ~21 of them target `/student/getkey` and `/student/restoreKey`,
   routes deleted when student pages moved to the SPA. The rest target live routes and
   should pass today.
2. **Manual grading is not actually tested.** `REFWebClient.grade_submission` posts to
   `/admin/grading/edit/{id}`, which does not exist (the real route is
   `POST /admin/grading/grade/<id>`) with the wrong field names. So
   `tests/e2e/test_grading_workflow.py::TestManualGrading`'s four tests only assert that
   `GET /admin/grading/` returns 200 — no grade is ever assigned.
3. **The scoreboard is untested on both sides.** No Python test touches
   `/api/scoreboard/*`, and the TypeScript ranking algorithm that decides placement
   (`spa-frontend/src/ranking/`, ~276 lines) has nothing exercising it.

Intended outcome: the SPA's behaviour is covered at two levels (fast vitest units and
real-browser Playwright flows), a catalogue of generated test exercises makes the
full student journey testable, and the dead `tests/api/` suite runs again.

## Constraints discovered (these shape the design — do not design around them twice)

**Exercise definition.** `ExerciseManager._from_yaml` accepts only `short-name`,
`version`, `entry`, `services`, plus four deprecated keys (`category`, `deadline`,
`submission-test`, `grading-points`); anything else is a hard error. `grading-points`
and `deadline` must both be set or neither.

**`ExerciseConfig` is keyed by `short_name` and shared across versions.** On import, an
existing config row wins and the YAML admin values are *ignored*. So YAML
deadline/category/grading-points only take effect on the **first** import of a given
`short_name` — every builder must therefore mint a unique `short_name` per test module.

**`per_task_scoring_policies` has no YAML representation at all.** It is settable only
via `POST /admin/exercise/config/<short_name>/edit` or by DB mutation through
`remote_exec`. Task names are discovered from the `submission_tests` file by AST
(`extract_task_names_from_submission_tests`), and a decorator without an explicit
`task_name` contributes the name `"default"`.

**Multi-task is a `submission_tests` concern, not a settings.yml one** —
`@submission_test(task_name="...")`, and a test may return
`TestResult(success, score)` instead of a bool. Confirmed exports in
`ref-docker-base/ref-utils/ref_utils/__init__.py`.

**Nothing reaches the scoreboard without a numeric task score.** A bool-returning task
stores `score=None`, which `score_submission` maps to `None` in the breakdown
contributing 0, and the SPA's `getRanking` filters out totals of 0. So the existing
single-task template can *never* appear on the scoreboard, and at least one exercise
returning `TestResult(success, score=<number>)` is mandatory for any scoreboard
assertion. A scoring *policy* is **not** required for this — `apply_scoring` passes the
raw score through when no policy is set. Policies are a separate axis to test
(`linear` / `threshold` / `tiered` / `discard`, plus the `baseline` key that the SPA's
`ChallengePlot` sums to draw its reference line).

**Scoreboard preconditions:** `SCOREBOARD_ENABLED` defaults to **False** (all three
`/api/scoreboard/*` endpoints 404 until flipped via `remote_exec`); `/config` lists only
exercises that are `FINISHED` + `is_default` + have a non-null `ExerciseConfig.category`;
and the public `/submissions` drops submissions made before
`cfg.submission_deadline_start`, so the deadline window must already be open.

**Grading visibility:** `grading_view_all` skips exercises with no deadline entirely, and
`is_current_user_allowed_to_view` gates grading-assistant access through
`SUBMISSION_HIDE_ONGOING` while a deadline is still open. A past-deadline exercise plus a
grading-assistant user is what makes this matrix testable.

**Grading and submitting need opposite deadline states, and this drives the whole design.**
`grading.py` refuses to save a grade unless `exercise.deadine_passed()`, while
`services_api/instance.py` refuses a submission once it has. There is no deadline state in
which both work, so a grading test cannot be built from a past-deadline exercise. The only
workable sequence is: **submit while the deadline is open, then move the deadline into the
past via the admin config form, then grade.** That also collapses what looked like two
exercises into one image build.

**`/admin/grading/` crashes on a mixed instance.** `grading_view_all` sorts
`Exercise.all()` by `(e.category, e.short_name, e.version)` *before* applying the
per-exercise visibility filter, and `Exercise.category` is `Optional[str]`. One
category-less exercise alongside a categorised one raises
`TypeError: '<' not supported between 'NoneType' and 'str'`. This is a production bug; it
means every generated exercise must carry a category unless the one-line fix is taken.

**`POST /admin/system/settings/` writes every field of a form group at once**, so a
partial POST blanks `COURSE_NAME`, `TIMEZONE` and the rest. System settings must therefore
be set through `SystemSettingsManager` via `remote_exec`, not over HTTP.

**Team labels** come from `team_identity(user)`: the group name when `GROUPS_ENABLED` and
the user has a group, else `"{first_name} {surname}"`.

**Test-suite mechanics.** `ref_instance` is **module-scoped** and boots a full docker
compose stack per test file (`startup_timeout=180`), so every new e2e module costs a
stack. `pytest.ini` runs `-n 10 --dist loadfile` with `timeout = 300`.
`tests/conftest.py::pytest_collection_modifyitems` **aborts the whole run** if a CLI
argument contains both `e2e/` and `::`, so new e2e files must be runnable whole; the
established pattern is ordered classes (`test_00_`, `test_01_`) sharing a module-scoped
mutable state holder. `web_client` and `admin_client` are **the same object** — logging
out of one de-authenticates the other.

**The SPA is already reachable in tests.** `ref_instance.web_url` is the published port of
the Caddy `frontend-proxy`, which serves the *baked* SPA bundle; `Caddyfile.routes` falls
`/spa/*` deep-links back to `index.html`, so Playwright can navigate directly to
`{web_url}/spa/register`, `/spa/restore-key`, `/spa/scoreboard`.

**Rate limiting** is off in test instances (`RATELIMIT_ENABLED=0`). The containers run
`DebugConfig`, which honours the env var, so rate-limit tests need an instance built with
`ratelimit_enabled=True` via `ref_instance_factory` — `config_test.py`'s hardcoded
`RATELIMIT_ENABLED = False` only affects in-process unit tests.

**System settings that drive SPA behaviour** (flip via `remote_exec`, following the
pattern in `tests/integration/test_groups_registration.py`): `REGESTRATION_ENABLED`
(note the spelling in `webapp/ref/model/settings.py`), `GROUPS_ENABLED`, `GROUP_SIZE`,
`SCOREBOARD_ENABLED`, `COURSE_NAME`, `LANDING_PAGE`, `SUBMISSION_HIDE_ONGOING`.

**CI** has no node/npm and no browser. The e2e job runs only `pytest e2e/` under a
30-minute cap; `integration/` and `api/` never run there.

date fixtures depend on which month you picked. Do **not** assert formatted date strings:
ICU's default locale differs between this box and CI. Build an equivalent
`Intl.DateTimeFormat` inside the test and compare, plus one structural assertion (e.g.
`formatAxisTime` output contains no year).

### 2. Exercise catalogue in `tests/helpers/exercise_factory.py` + templates

**Refactor onto one primitive.** `write_exercise(exercise_dir, settings, files=None,
submission_tests=None)` writes `settings.yml` + payload files + an executable
`submission_tests`, absorbing the `if exercise_dir.exists(): shutil.rmtree(...)`
boilerplate currently copy-pasted into every e2e module, and validating `short-name`
against the webapp's regex so a bad name fails locally instead of inside `remote_exec`.

**Collision safety, enforced by the factory rather than by convention** (this is the
`ExerciseConfig`-is-keyed-by-`short_name` hazard):
- `unique_short_name(stem)` → `f"{stem}_{uuid4().hex[:6]}"` is the only sanctioned way to
  mint one.
- **`short_name` becomes a required positional argument on every builder**, including
  `create_sample_exercise` — its current `short_name="test_exercise"` default is exactly
  how two tests end up sharing a config row. Two call sites to update:
  `tests/conftest.py::sample_exercise_path` and `tests/integration/conftest.py`.
- Deliberate sharing is explicit: `write_exercise_version(parent_dir, short_name,
  version, ...)` writes to `parent_dir / f"{short_name}_v{version}"` so the import path
  differs while the `short_name` matches. Accidental sharing becomes unwriteable.

**The catalogue.** The expensive unit is the docker build, not the YAML, so anything
coverable without a build is, and anything needing one is packed into as few exercises as
possible.

| Builder | Build? | What it unlocks |
|---|---|---|
| `create_sample_exercise` (existing, `short_name` now required) | yes | back-compat for the 5 modules already using it |
| `create_multi_task_exercise` | yes | **the centrepiece** — see below |
| `create_past_deadline_exercise` | yes | the currently-skipped `test_cannot_submit_after_deadline`; the GA visibility matrix; the red "Deadline: Passed" banner branch |
| `create_ungraded_exercise` | no | the distinct open-end submit rejection; exclusion from `/api/scoreboard/config`. **Defaults to a non-`None` category** because of the `grading_view_all` crash |

`create_multi_task_exercise` is the one that unblocks the scoreboard. A Python payload

Keep the existing `templates/submission_tests.py` unchanged; its single undecorated task
means policy dicts for it are keyed `"default"`.

### 3. Helper fixes and additions

Split rule: **`web_client` (HTTP) when a view function owns the logic; `method_exec`
(`remote_exec`) when the only sane writer is a manager with no usable HTTP form.**

**`tests/helpers/web_client.py` (HTTP):**
- `grade_submission` — two independent bugs: the route
  (`/admin/grading/edit/{id}` doesn't exist; it's `POST /admin/grading/grade/<id>`) and
  the field names (`GradingForm` has `points`, `notes` and submit fields
  `save`/`save_and_next`/`save_next_user_task`/`reset` — there is no `comment` and no
  `private_note`). The `points: float` signature is wrong too; it's an `IntegerField`.
  New signature takes an `action` selecting the submit field, and returns
  `(ok, flash_errors)` — a rejected grade re-renders with HTTP 200, so the status code
  alone is not a verdict.
- `set_exercise_config(short_name, *, category, deadline_start, deadline_end,
  submission_test_enabled, max_grading_points, per_task_scoring_policies,
  new_short_name)` → `POST /admin/exercise/config/<short_name>/edit`. **This is how
  scoring policies get set**, not a DB mutation: there is no manager for that column —
  the view *is* the business logic, and a `remote_exec` write would both violate the
  project's no-direct-model-writes rule and skip the three validators that are the most
  interesting untested code in the feature (`_per_task_policies_from_form`,
  `validate_scoring_policy`, `_discover_tasks_for_config`'s AST walk). Details that cost
  an afternoon otherwise: `category` is `DataRequired`; datetimes are `%Y-%m-%dT%H:%M`,
  both or neither; `submission_test_enabled` is a `BooleanField`, so send `"y"` when true
  and **omit the key** when false; `per_task_scoring_policies_json` is `json.dumps(...)`
  and an empty string sets the column to `NULL`; include `submit: "Save"`. **It must be
  called after `toggle_exercise_default` and after the build**, or discovery returns `[]`,
  the unknown-task check is skipped, and validation silently no-ops.
- New `get_submission_ids(exercise_id)`, `get_grading(submission_id)`,
  `get_exercise_config(short_name)` replacing the stubs. Prefer asserting config
  round-trips through `/api/scoreboard/config` where the data is already JSON; scrape the
  form only for `max_grading_points` and `submission_test_enabled`.
- **Delete** `set_exercise_as_default` (nonexistent route; `toggle_exercise_default` is
  the real one) and the five always-`None`/`[]`/`False` stubs once replacements exist. A
  stub returning `False` is worse than a missing method, because tests assert on it and
  pass.
- Deadline read-back goes through `datetime_transmute_into_local` with `TIMEZONE`
  defaulting to `Europe/Berlin`. Set `TIMEZONE` to `UTC` in the scoring module's setup
  rather than asserting with a tolerance.

**`tests/helpers/method_exec.py` (`remote_exec`):**
- `set_system_setting(name, value)` / `get_system_setting(name)`, with the setter
  returning the previous value, plus a `system_setting(...)` context manager that
  restores. HTTP is wrong here (a partial settings POST blanks the rest of the group), and
  `SystemSettingsManager` *is* the manager class. Note the `Setting.value` setter only

  `SUBMISSION_HIDE_ONGOING`, `SUBMISSION_DISABLED`, `LANDING_PAGE`, `TIMEZONE`,
  `GROUPS_ENABLED`.
- `create_grading_assistant(...)` — `UserManager` has no role API, so this replicates
  `ref/view/student.py`'s `auth_groups = [STUDENT, GRADING_ASSISTANT]` assignment, which
  is the project's second sanctioned pattern.

**`tests/conftest.py`:** un-alias `web_client` and `admin_client`. They are currently the
same object, which is why `test_grading_workflow.py` has to re-login mid-file. Introduce a
module-scoped `web_client_factory`, then `web_client` (anonymous), `admin_client`

and therefore every test, so it lands as its own step with a full e2e re-run; none of the
